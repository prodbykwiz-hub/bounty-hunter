# Bounty Hunter

Бот раз в 15 минут ищет на GitHub открытые оплачиваемые issues (bounties) на C++ и Python,
отсеивает спам и присылает свежие задачи в Telegram. Работает бесплатно на GitHub Actions,
сервер не нужен.

## Структура

```
bounty-hunter/
├── .github/
│   └── workflows/
│       └── bounty_hunter.yml   # cron каждые 15 мин + коммит состояния
├── main.py                     # бот: поиск → фильтры → Telegram
├── requirements.txt            # requests
├── seen_issues.json            # уже обработанные issues (обновляет бот)
├── .gitattributes
├── .gitignore
└── README.md
```

## Как работает

1. **Поиск.** 10 запросов к GitHub Search API: каждый язык (`C++`, `Python`) × каждый признак
   (`label:bounty`, `label:"💎 Bounty"`, `algora`, `opire`, `bounty in:title`), только
   `is:issue is:open no:assignee`, созданные за последние `MAX_AGE_HOURS`.
   GitHub Search игнорирует символ `$`, поэтому сумму в заголовке ищем по слову `bounty`,
   а саму сумму достаём регуляркой.
2. **Спам по тексту** (без запросов к API): стоп-слова (`Bounty Seguro`, `escrow`,
   `Trauma-Station`, `airdrop`, `seed phrase`…) в заголовке, теле и нике автора; ссылки
   на сокращатели, IP-адреса, подозрительные домены (`.xyz`, `.top`…) и домены-приманки
   вроде `github-reward-claim.com`.
3. **Проверка репозитория** одним GraphQL-запросом на пачку: меньше 30 ⭐ или 5 форков,
   архив, иероглифы в репозитории меньше чем на 100 ⭐ — пропуск.
4. **Конкуренция.** Комментарии с `/attempt`, `assign me`, `working on this` от разных людей
   (боты Algora/Opire не считаются). Больше 3 — пометка «Высокая конкуренция»
   или пропуск (`SKIP_HIGH_COMPETITION=true`).
5. **Telegram.** Заголовок-ссылка, репозиторий, ⭐, язык, награда, число комментариев,
   «Опубликовано N минут назад».

Отправленные задачи и спам записываются в `seen_issues.json`, поэтому одна задача не придёт
дважды. Задачи, отсеянные из‑за звёзд, не запоминаются: если репозиторий наберёт звёзды,
задача придёт позже. Лимиты GitHub API (основной и secondary) и flood control Telegram
обрабатываются автоматически: бот ждёт и повторяет запрос.

## Установка: 5 шагов

1. **Создай бота в Telegram.** Напиши [@BotFather](https://t.me/BotFather) → `/newbot` →
   скопируй токен вида `123456:ABC...`. Это `TG_BOT_TOKEN`.
2. **Узнай `TG_CHAT_ID`.** Напиши своему боту любое сообщение (для группы — добавь бота в
   группу и напиши там), затем открой в браузере
   `https://api.telegram.org/bot<TG_BOT_TOKEN>/getUpdates` и найди `"chat":{"id":...}`.
   У групп id отрицательный, например `-1001234567890`.
3. **Залей проект на GitHub.** Создай репозиторий и запушь в него эту папку
   (про выбор между публичным и приватным см. раздел ниже).
4. **Добавь секреты.** В репозитории: **Settings → Secrets and variables → Actions →
   New repository secret**:
   - `TG_BOT_TOKEN` — токен из шага 1;
   - `TG_CHAT_ID` — id из шага 2;
   - `GITHUB_TOKEN` **создавать не нужно и нельзя**: GitHub запрещает секреты с префиксом
     `GITHUB_`. Workflow сам берёт встроенный токен, его хватает для поиска.
     Если хочешь свой токен (Personal Access Token без каких‑либо прав доступа),
     положи его в секрет `GH_PAT`.
5. **Запусти.** **Actions → Bounty Hunter → Run workflow**: первый запуск пройдёт сразу,
   дальше бот запускается по расписанию. Если шаг `Commit seen_issues.json` упал с 403,
   значит запись запрещена политикой репозитория или организации: включи
   **Settings → Actions → General → Workflow permissions → Read and write permissions**.

## Минуты GitHub Actions: публичный или приватный репозиторий

Каждый запуск оплачивается как минимум одной минутой.

| Репозиторий | Лимит Free | Cron `*/15` (2880 мин/мес) |
|---|---|---|
| Публичный | без ограничений | бесплатно |
| Приватный | 2000 мин/мес | лимит кончится на ~21‑й день, Actions остановятся до следующего месяца |

- **Публичный репозиторий** — самый простой вариант. Секреты в нём не видны никому,
  а в `seen_issues.json` только ссылки на публичные issues.
- **Приватный репозиторий** — поменяй в `.github/workflows/bounty_hunter.yml`
  `cron: "*/15 * * * *"` на `cron: "*/25 * * * *"` (~1730 мин/мес).

Если в репозитории 60 дней нет активности, GitHub может отключить расписание. Включается
обратно кнопкой **Enable workflow** во вкладке Actions.

## Настройки

Необязательные. Задаются в **Settings → Secrets and variables → Actions → Variables**.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `LANGUAGES` | `C++,Python` | Языки через запятую |
| `MIN_STARS` | `30` | Минимум звёзд у репозитория |
| `MIN_FORKS` | `5` | Минимум форков |
| `MAX_AGE_HOURS` | `72` | Искать issues не старше N часов |
| `COMPETITION_THRESHOLD` | `3` | Сколько претендентов считать высокой конкуренцией |
| `SKIP_HIGH_COMPETITION` | `false` | `true` — не присылать такие задачи вовсе |
| `MAX_MESSAGES_PER_RUN` | `20` | Максимум сообщений за запуск, чтобы не завалить чат |

Только для локального запуска: `DRY_RUN`, `STATE_FILE`, `STATE_TTL_DAYS`, `LOG_LEVEL`.

## Локальный запуск

```bash
pip install -r requirements.txt
```

Пробный запуск без Telegram: печатает сообщения в лог и не меняет `seen_issues.json`
(нужен GitHub-токен):

```bash
GITHUB_TOKEN=ghp_xxx DRY_RUN=1 python main.py
```
