# Bounty Hunter

Бот раз в 15 минут ищет на GitHub открытые оплачиваемые issues (bounties) на C++, Python, Rust и Go,
отсеивает спам и присылает свежие задачи в Telegram. Работает бесплатно на GitHub Actions,
сервер не нужен.

## Структура

```
bounty-hunter/
├── .github/
│   └── workflows/
│       └── bounty_hunter.yml   # cron каждые 15 мин + коммит состояния
├── main.py                     # сканер: поиск → фильтры → карточка в Telegram
├── agent/                      # локальный агент (python -m agent)
│   ├── __main__.py             # кнопки Telegram, наблюдатель, жизненный цикл задачи
│   ├── github.py               # gh CLI + защита от чужого аккаунта
│   ├── gemini.py               # Gemini API: только тексты сообщений
│   ├── coder.py                # Claude Code CLI (claude -p) решает задачу
│   ├── workspace.py            # клон, ветка, коммит, diff, push
│   ├── prompts.py              # промпты
│   ├── report.py               # ежедневный отчёт в Telegram
│   ├── keepalive.py            # /health и самопинг для бесплатного Render
```

## Как работает

1. **Поиск.** 3 запроса к GitHub Search API: `label:bounty,"💎 Bounty"`, `algora OR opire`,
   `bounty in:title`. Ищутся только `is:issue is:open no:assignee`, созданные за последние
   `MAX_AGE_HOURS` (по умолчанию 30 дней), с паузой 6 с между запросами: на частых поисках
   GitHub включает secondary rate limit. Поиск отдаёт не больше 200 самых новых результатов,
   а за месяц их сотни, поэтому в каждом запуске проверяются последние сутки и ещё один
   двухдневный срез месяца по очереди. Весь месяц проходится примерно за 3,5 часа.
   Язык в запрос не входит, его проверяем по репозиторию (шаг 3).
   GitHub Search игнорирует символ `$`, поэтому сумму в заголовке ищем по слову `bounty`,
   а саму сумму достаём регуляркой.
   **Платформы.** Плюс к поиску бот берёт активные награды из открытого API
   [Opire](https://opire.dev) (`api.opire.dev/rewards`, без ключа). Сумма там точная, а сами
   issues проходят те же фильтры, что и найденные поиском. У Algora открытого списка всех
   баунти нет, но её задачи — обычные GitHub issues с ботом Algora, их находит поиск.
   IssueHunt, BountyHub и Gitpay публичного API не дают.
2. **Спам по тексту** (без запросов к API): issues, созданные ботами (новостные ленты,
   авто-intake); стоп-слова (`Bounty Seguro`, `escrow`,
   `Trauma-Station`, `airdrop`, `seed phrase`…) в заголовке, теле и нике автора; ссылки
   на сокращатели, IP-адреса, подозрительные домены (`.xyz`, `.top`…) и домены-приманки
   вроде `github-reward-claim.com`.
3. **Проверка репозитория** одним GraphQL-запросом на пачку: меньше 30 ⭐ или 5 форков,
   архив, основной язык не из `LANGUAGES`, иероглифы в репозитории меньше чем на 100 ⭐ —
   пропуск.
   **Награда обязательна:** без суммы в метках, заголовке, теле или комментарии бота задача
   не приходит. Сумма засчитывается только вместе с признаком баунти: меткой bounty,
   упоминанием Algora или Opire, либо словом bounty рядом с суммой в заголовке.
   С одного репозитория приходит не больше 3 задач за прогон.
4. **Конкуренция.** Комментарии с `/attempt`, `assign me`, `working on this` от разных людей
   (боты Algora/Opire не считаются). Больше 3 — пометка «Высокая конкуренция»
   или пропуск (`SKIP_HIGH_COMPETITION=true`).
5. **Telegram.** Заголовок-ссылка, репозиторий, ⭐, язык, награда, число комментариев,
   «Опубликовано N минут назад».

Отправленные задачи и спам записываются в `seen_issues.json`, поэтому одна задача не придёт
дважды. Задачи, отсеянные из‑за звёзд, не запоминаются: если репозиторий наберёт звёзды,
задача придёт позже. Лимиты GitHub API (основной и secondary) и flood control Telegram
обрабатываются автоматически: бот ждёт и повторяет запрос.

## Установка: 5 шагов

1. **Создай бота в Telegram.** Напиши [@BotFather](https://t.me/BotFather) → `/newbot` →
   скопируй токен вида `123456:ABC...`. Это `TG_BOT_TOKEN`.
2. **Узнай `TG_CHAT_ID`.** Напиши своему боту любое сообщение (для группы — добавь бота в
   группу и напиши там), затем открой в браузере
   `https://api.telegram.org/bot<TG_BOT_TOKEN>/getUpdates` и найди `"chat":{"id":...}`.
   У групп id отрицательный, например `-1001234567890`.
3. **Залей проект на GitHub.** Создай репозиторий и запушь в него эту папку
   (про выбор между публичным и приватным см. раздел ниже).
4. **Добавь секреты.** В репозитории: **Settings → Secrets and variables → Actions →
   New repository secret**:
   - `TG_BOT_TOKEN` — токен из шага 1;
   - `TG_CHAT_ID` — id из шага 2;
   - `GITHUB_TOKEN` **создавать не нужно и нельзя**: GitHub запрещает секреты с префиксом
     `GITHUB_`. Workflow сам берёт встроенный токен, его хватает для поиска.
     Если хочешь свой токен (Personal Access Token без каких‑либо прав доступа),
     положи его в секрет `GH_PAT`.
5. **Запусти.** **Actions → Bounty Hunter → Run workflow**: первый запуск пройдёт сразу,
   дальше бот запускается по расписанию. Если шаг `Commit seen_issues.json` упал с 403,
   значит запись запрещена политикой репозитория или организации: включи
   **Settings → Actions → General → Workflow permissions → Read and write permissions**.

## Минуты GitHub Actions: публичный или приватный репозиторий

Каждый запуск оплачивается как минимум одной минутой.

| Репозиторий | Лимит Free | Cron `*/15` (2880 мин/мес) |
|---|---|---|
| Публичный | без ограничений | бесплатно |
| Приватный | 2000 мин/мес | лимит кончится на ~21‑й день, Actions остановятся до следующего месяца |

- **Публичный репозиторий** — самый простой вариант. Секреты в нём не видны никому,
  а в `seen_issues.json` только ссылки на публичные issues.
- **Приватный репозиторий** — поменяй в `.github/workflows/bounty_hunter.yml`
  `cron: "*/15 * * * *"` на `cron: "*/25 * * * *"` (~1730 мин/мес).

Если в репозитории 60 дней нет активности, GitHub может отключить расписание. Включается
обратно кнопкой **Enable workflow** во вкладке Actions.

## Настройки

Необязательные. Задаются в **Settings → Secrets and variables → Actions → Variables**.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `LANGUAGES` | `C++,Python,Rust,Go` | Языки через запятую |
| `MIN_STARS` | `30` | Минимум звёзд у репозитория |
| `MIN_FORKS` | `5` | Минимум форков |
| `MIN_REWARD` | `25` | Минимальная награда в $ (меньше — обычно цена или пример в тексте) |
| `MAX_AGE_HOURS` | `720` | Искать issues не старше N часов (720 — 30 дней) |
| `COMPETITION_THRESHOLD` | `3` | Сколько претендентов считать высокой конкуренцией |
| `SKIP_HIGH_COMPETITION` | `false` | `true` — не присылать такие задачи вовсе |
| `MAX_MESSAGES_PER_RUN` | `20` | Максимум сообщений за запуск, чтобы не завалить чат |
| `PLATFORMS` | `opire` | Внешние платформы через запятую; `none` — только поиск GitHub |
| `GIGS` | `superteam` | Заказы вне GitHub: `superteam`, `freelancer` через запятую; `none` — выключить |
| `GIG_MAX_PER_RUN` | `10` | Максимум карточек заказов за запуск с каждой площадки |
| `GIG_MIN_USD` | `30` | Минимальный бюджет заказа в $ (верхняя граница вилки) |
| `GIG_MAX_COMPETITORS` | `30` | Freelancer: пропускать заказы, где ставок больше |
| `GIG_MAX_AGE_HOURS` | `24` | Freelancer: заказы не старше N часов |
| `SUPERTEAM_CATEGORY` | `All` | `All`, `Development`, `Content`, `Design` или `Other` |
| `FREELANCER_JOBS` | код | id категорий Freelancer через запятую, см. `agent/gigs.py` |

Только для локального запуска: `DRY_RUN`, `STATE_FILE`, `STATE_TTL_DAYS`, `LOG_LEVEL`.

## Локальный запуск

```bash
pip install -r requirements.txt
```

Пробный запуск без Telegram: печатает сообщения в лог и не меняет `seen_issues.json`
(нужен GitHub-токен):

```bash

```

## Локальный агент: ответ, согласие, решение, PR

Сканер в Actions только присылает карточки. Всё остальное делает агент на твоём ПК:

1. **✍️ взять** — Gemini пишет ответ в issue в твоём стиле (`agent/style.md`). Если Gemini
   недоступен (Google закрывает API для части стран, бывают 503 и лимиты), текст пишет
   Claude CLI без инструментов. Gemini можно пустить через прокси: `GEMINI_PROXY` в `.env`. Если в
   `CONTRIBUTING.md` репозитория есть правила про AI, карточка их покажет.
   Кнопки: **отправить / переписать / отмена**. Ответь на сообщение текстом
   («короче», «без вопроса»), и черновик перепишется с учётом правки.
2. **Отправить** — комментарий публикуется от `prodbykwiz-hub`. Для Algora первой строкой
   идёт `/attempt #N`.
3. **Наблюдатель** раз в 5 минут смотрит issue:
   - тебя назначили или мейнтейнер согласился → начинается работа;
   - отказали, назначили другого, закрыли или 14 дней тишины → задача снимается;
   - мейнтейнер задал вопрос → приходит черновик ответа на него.
4. **Работа** — репозиторий клонируется в `WORK_DIR`, создаётся ветка `bounty/N-...`, и код
   пишет **Claude** через Claude Code CLI (`claude -p`, по твоей подписке). Gemini код не
   пишет, на нём только тексты сообщений. У Claude только файловые инструменты (`Read`,
   `Edit`, `Write`, `Glob`, `Grep`), без MCP и без настроек и хуков из клонированного репо.
   **Команды он не запускает:** текст issue пишут посторонние, и через prompt injection он не
   должен выполнить код на твоём ПК. Тесты запускаешь сам.
5. **Ревью** — в Telegram приходит итог, список файлов и `.patch`. Ответь текстом, чтобы
   доработать, или нажми **🚀 открыть PR**: форк → push → PR с `closes #N`
   (и `/claim #N` для Algora).

`/status` в чате бота — список задач в работе, `/report` — отчёт за сутки. Отчёт приходит и сам,
раз в день в `REPORT_HOUR` по UTC (по умолчанию 6, то есть 09:00 МСК; `none` — не слать).

**Запуск сканера.** Cron в GitHub Actions на новых репозиториях выполняется с большими
пропусками (бывает пара запусков за ночь вместо десятков). Поэтому агент, пока он работает,
сам запускает workflow сканера раз в 15 минут через `workflow_dispatch`, а такие запуски
GitHub выполняет всегда. Если сканер уже идёт или только что отработал по cron, запуск
пропускается. Пока ПК выключен, остаётся cron. Настройки в `.env`: `SCAN_REPO`
(по умолчанию `<GITHUB_USER>/bounty-hunter`, `none` — не запускать), `SCAN_INTERVAL` в секундах.

### Установка агента

1. **gh под `prodbykwiz-hub`.** `gh auth switch` переключает только между уже добавленными
   аккаунтами, поэтому сначала добавь `prodbykwiz-hub`:

   ```bash
   gh auth login --hostname github.com --git-protocol https --web
   ```

   gh покажет код и откроет `github.com/login/device`. **Открой эту ссылку в приватном окне
   и войди как `prodbykwiz-hub`**: в обычном окне браузер подставит залогиненный там аккаунт,
   и gh снова авторизует его. Потом проверь:

   ```bash
   gh auth status
   ```

   Активным должен быть `prodbykwiz-hub`. Пока это не так, агент не запустится: перед любой
   записью на GitHub он проверяет аккаунт.
2. **`.env`.** Проще всего через мастер: `py -3 setup_env.py`. Он спросит токен бота и ключ
   Gemini, проверит их и сам определит id чата и твой id по сообщению боту.
   Можно и вручную: скопируй `.env.example` в `.env` и заполни. `TG_OWNER_ID` — твой числовой id:
   напиши боту, открой `https://api.telegram.org/bot<TG_BOT_TOKEN>/getUpdates` и возьми
   `"from":{"id":...}`. Ключ Gemini: <https://aistudio.google.com/apikey>.
3. **Стиль.** Поправь `agent/style.md`: правила и 2–3 примера твоих настоящих сообщений.
4. **Запуск:**

   ```bash
   py -3 -m agent
   ```

5. **Автозапуск при входе в Windows** (лог в `agent.log`). Подставь свой путь к папке проекта:

   ```bash
   schtasks /Create /SC ONLOGON /TN BountyAgent /TR "\"C:\path\to\bounty-hunter\run_agent.cmd\""
   ```

Пока агент выключен, нажатия кнопок копятся в Telegram (до 24 часов) и обработаются после
запуска. Задача, прерванная перезапуском, придёт с кнопкой **🔁 ещё раз**.

## Заказы: Superteam Earn и Freelancer

Кроме issues на GitHub сканер присылает заказы с двух площадок. Ключи не нужны: обе отдают
ленту открытым API.

- **Superteam Earn** — конкурсы и проекты экосистемы Solana, оплата в USDC/USDG.
  Открытых заказов обычно около десятка, большинство про контент (видео, треды), код встречается
  редко. Пометка «🤖 можно агенту» значит, что площадка принимает работы от ИИ-агентов.
- **Freelancer.com** — обычный фриланс. Берутся только категории кода
  (C++, Python, Rust, Go, Docker, Linux). Заказы про озвучку, музыку и видео отсеиваются, даже если
  на них стоит тег Python. Конкуренция высокая (на популярных заказах 50–200 ставок),
  поэтому бот пропускает заказы старше суток и с большим числом ставок.

На карточке заказа кнопка **✍️ отклик**: агент открывает полное описание и пишет черновик
по фактам из `agent/gig_profile.md`. Чего нет в профиле (ссылки на работы, цену, сроки), модель
не выдумывает, а оставляет в `[скобках]`. Отправляешь отклик сам на площадке и жмёшь
**✅ отправил**: так отчёт считает отклики. Сам бот на площадках ничего не отправляет.

**Правила площадок, прочитай до включения.**
- Freelancer в разделе 33 условий запрещает заходить на сайт роботами и скриптами,
  «в том числе через API», без письменного разрешения. Поэтому по умолчанию он выключен
  (`GIGS=superteam`). Включаешь ты сам и на свой риск: `GIGS=superteam,freelancer`.
- Freelancer пускает с 16 лет, а с 16 до 18 только через аккаунт взрослого с его разрешения
  (раздел 3 условий).
- Вывод денег с Freelancer для России не проверен. Superteam платит в стейблкоинах на кошелёк Solana.

## Агент на Render: работает без ПК, бесплатно

Агент работает на [Render](https://render.com) как бесплатный веб-сервис, ПК для этого не нужен. От тебя
только кнопки в Telegram. Сканер остаётся в GitHub Actions, агент запускает его раз в 15 минут.
Каждое утро приходит отчёт (запуски сканера, присланные карточки, задачи, ошибки), а `/report`
в чате бота присылает его сразу. Всё нужное лежит в репозитории: `Dockerfile`, `docker-entrypoint.sh`
и `render.yaml`.

**Как обходятся ограничения бесплатного тарифа** ([render.com/docs/free](https://render.com/docs/free)):

- Фоновые воркеры бывают только платными. Поэтому агент оформлен как веб-сервис: отвечает на `/health`.
- Сервис засыпает после 15 минут без входящих запросов. Агент раз в 5 минут сам запрашивает свой
  адрес (`RENDER_EXTERNAL_URL`), а если всё-таки уснул, его будит сканер в Actions. Для этого задай
  переменную `AGENT_URL`, о ней ниже.
- Постоянного диска нет, поэтому состояние задач раз в минуту сохраняется в секретный gist
  `bounty-agent state` и восстанавливается при старте. Ссылка на gist нигде не публикуется, но
  открыть его может любой, кто её знает. Токенов там нет, только задачи и черновики.
- Клоны репозиториев при перезапуске пропадают. Если это случится между ревью и PR, бот предложит
  **🔁 ещё раз**, и Claude напишет код заново.
- Месяц бесплатно — это 750 часов, одному сервису хватает на круглосуточную работу. Процессор
  слабый (0.1 CPU), поэтому Claude на больших репозиториях работает медленнее, чем на ПК.

**Два токена, без них агент на сервере не работает:**

- **Claude:** на своём ПК выполни `claude setup-token`, войди подпиской и скопируй токен
  (действует год). Это `CLAUDE_CODE_OAUTH_TOKEN`.
- **GitHub:** токен `prodbykwiz-hub` со scopes `repo`, `workflow` и `gist`. У gh они уже есть.
  `gh auth token --user prodbykwiz-hub | clip` кладёт токен в буфер, не показывая на экране.
  Это `GH_TOKEN`.

**Развёртывание:**

1. На render.com открой **New → Blueprint** и выбери репозиторий `bounty-hunter`. Тариф Free,
   карта не нужна.
2. Введи секреты: `TG_BOT_TOKEN`, `TG_CHAT_ID`, `TG_OWNER_ID`, `GEMINI_API_KEY` (возьми из своего
   `.env`), `GH_TOKEN` и `CLAUDE_CODE_OAUTH_TOKEN`.
3. **Deploy Blueprint.** Когда сборка закончится, скопируй адрес сервиса (`https://bounty-agent-….onrender.com`)
   и добавь его в репозиторий как переменную `AGENT_URL`: Settings → Secrets and variables →
   Actions → Variables.
4. **Останови агента на ПК.** Два агента с одним ботом мешают друг другу: Telegram отдаёт
   нажатия только одному, второй получает `409 Conflict`.

Сервер стоит во Франкфурте, оттуда Gemini API доступен без прокси. При пуше в `agent/`,

`seen_issues.json` пересборку не запускают.
